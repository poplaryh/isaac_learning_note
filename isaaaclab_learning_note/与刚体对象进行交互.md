# 五、创建刚体对象

这是本教程最核心的部分。

首先创建：

```python
cone_cfg = RigidObjectCfg(
```

也就是说，我们不是直接创建一个普通的 `ConeCfg`，而是把它包装到：

```python
RigidObjectCfg
```

中。

完整代码：

```python
cone_cfg = RigidObjectCfg(
    prim_path="/World/Origin.*/Cone",

    spawn=sim_utils.ConeCfg(
        radius=0.1,
        height=0.2,
        rigid_props=sim_utils.RigidBodyPropertiesCfg(),
        mass_props=sim_utils.MassPropertiesCfg(mass=1.0),
        collision_props=sim_utils.CollisionPropertiesCfg(),
        visual_material=sim_utils.PreviewSurfaceCfg(
            diffuse_color=(0.0, 1.0, 0.0),
            metallic=0.2
        ),
    ),

    init_state=RigidObjectCfg.InitialStateCfg(),
)
```

然后：

```python
cone_object = RigidObject(cfg=cone_cfg)
```

# 六、理解 RigidObjectCfg

这里可以把 `RigidObjectCfg` 理解成：

> “如何创建和管理这个刚体对象”的完整配置。

它包含几个重要部分。

---

## 1. `prim_path`

```python
prim_path="/World/Origin.*/Cone"
```

这里使用了正则表达式：

```text
.*
```

表示匹配：

```text
/World/Origin0/Cone
/World/Origin1/Cone
/World/Origin2/Cone
/World/Origin3/Cone
```

因此一个 `RigidObject` 配置可以对应多个实际的 Prim。

例如：

```text
/World/Origin0
```

存在时，就生成：

```text
/World/Origin0/Cone
```

同理：

```text
/World/Origin1
```

会生成：

```text
/World/Origin1/Cone
```

等等。

因此这里展示了一个非常重要的能力：

> **通过 Prim path 的正则表达式，可以一次管理多个相同的刚体对象。**


# 代码背后的核心思想

## 1. `design_scene()` 和 `run_simulator()` 必须分开理解

这个教程把 `main()` 拆成两个主要阶段：

### 第一阶段：Design scene

负责：

> 把所有 Prim 添加到场景中。

### 第二阶段：Run simulation

负责：

> 推进模拟器，并与场景中的 Prim 进行交互。

例如：

- 改变位置；
- 改变姿态；
- 设置速度；
- 施加外力；
- 读取状态。



---

## 为什么一定要区分这两个阶段？

因为：

> 第二阶段必须发生在第一阶段完成并执行 `sim.reset()` 之后。

模拟器 reset 后会自动开始播放仿真。

一旦仿真已经启动，就不应该再动态添加新的、带物理属性的 Prim。

否则可能导致不可预期的行为。

但是：

> 已经创建好的 Prim 仍然可以通过它们对应的 handle 进行交互。

这也是 `RigidObject` 这类资产管理器存在的重要原因。

# 28. `RigidObject` 到底做了什么？

前一个教程只是这样：

```python
cfg = sim_utils.ConeCfg(...)

```

这主要负责：

> **把 Cone Prim 生成到 USD Stage。**

而现在进一步使用：

```python
RigidObjectCfg
        ↓
RigidObject
```

于是 Isaac Lab 不仅创建了这个对象，还为它建立了：

> **刚体物理句柄（rigid body physics handles）**

因此我们可以进一步：

```python
cone_object.data
```

读取状态；

```python
cone_object.write_root_pose_to_sim(...)
```

修改位置和姿态；

```python
cone_object.write_root_velocity_to_sim(...)
```

修改速度；

```python
cone_object.update(...)
```

更新状态。

这就是从：

```text
“场景里有一个物体”
```

进化到：

```text
“Isaac Lab 可以程序化地控制和读取这个物体”
```

的关键一步。

# 29. 一个非常重要的概念：World Frame

教程特别强调：

当我们重置刚体时，使用的 root state 是在：

```text
Simulation World Frame
```

即：

> **仿真世界坐标系**

中定义的。

而不是在其父级：

```text
Xform
```

的局部坐标系中定义。

例如：

```text
/World/Origin1
    └── Cone
```

虽然 Cone 是 Origin1 的子对象，但物理引擎真正理解的是：

```text
World Frame
```

而不是：

```text
Origin1 Frame
```

因此，在设置刚体状态之前，必须首先把期望状态转换到世界坐标系。

这是本教程中非常重要的一个概念。

# 32. 本教程的核心总结

这个教程真正要学习的是：

```text
ConeCfg
```

只是用于：

> 定义如何生成一个圆锥 Prim。

而：

```text
RigidObjectCfg
```

进一步描述：

> 一个刚体资产应该如何生成、默认状态是什么，以及相关元信息。

再通过：

```text
RigidObject
```

真正实现：

> 对刚体物理对象进行创建、读取、修改和状态更新。

因此可以记成：

```text
普通 Prim
    ↓
spawn configuration
    ↓
只解决“怎么生成”

RigidObject
    ↓
RigidObjectCfg
    ↓
解决“怎么管理这个刚体”
```

下一个教程将继续在这个基础上介绍：

> **Articulated Object（多刚体关节系统）**

也就是由多个刚体通过关节连接而成的机器人或机械结构。
